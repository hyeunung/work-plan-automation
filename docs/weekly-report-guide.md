# 스마트팜 주간업무 보고 작성 지침

> 이 문서는 매주 주간업무 보고서를 동일한 형식으로 뽑기 위한 지침입니다.
> AI에게 "이 지침대로 이번 주 주간보고 뽑아줘" 라고 요청하면 이 형식 그대로 나옵니다.

---

## 1. 요청 방법

새 대화창에서 아래 링크를 함께 던지고 요청하세요.

```
https://github.com/hyeunung/work-plan-automation/blob/main/weekly-report-guide.md
이 지침대로 이번 주 주간업무 보고 뽑아줘.
```

또는 짧게:

```
지침 파일 참고해서 [YYYY-MM-DD ~ YYYY-MM-DD] 주간업무 보고 뽑아줘.
```

## 2. 데이터 소스

- **Notion Daily Work Log DB**: 세 담당자의 일일 업무 기록이 있는 곳 → "지난주 진행 내용" 섹션의 근거
- **Notion Weekly Plan DB**: 세 담당자의 주간 계획이 있는 곳 → "3. 이번 주 계획" 섹션의 근거 (이번 주 계획이 아직 등록 전이면, 지난주 미완료 항목과 일지에 언급된 예정 업무로 작성)
- **GitHub `work-plan-automation` repo**: 자동화 코드 (참고용)
- 세 담당자의 Notion 계정으로 필터링해서 지난주 스마트팜 관련 페이지만 취합

## 3. 취합 규칙

### 대상 인원 (3명)
- **김윤회** — 무인대차 파트
- **최현빈** — 무인대차 파트
- **김희승** — 스마트팜 제어 파트

### 범위
- **스마트팜 프로젝트 업무만 포함**
- 그 외 업무(개인 스터디성 항목, 다른 프로젝트, 사내 잡무 등)는 **제외**

### 파트 묶음
- 김윤회 · 최현빈 → 하나로 묶어서 "**무인대차 파트**" 로 서술
- 김희승 → 단독으로 "**스마트팜 제어 파트**" 로 서술
- 개별 담당자 이름을 문장 안에 따로 언급하지 않음 ("두 사람이", "김윤회가" 같은 표현 금지). 파트 단위로만 서술.

### 기간
- **지난주 월요일 ~ 금요일** (보고기간 표기도 월~금으로. 예: `보고기간: 2026년 7월 20일 ~ 7월 24일`)
- 단, 주말에 기록된 업무가 있으면 내용에는 포함 (기간 표기만 월~금)

## 4. 보고서 형식 (반드시 이 구조 그대로)

### 구성 순서
1. **제목**: `스마트팜 주간업무 보고`
2. **보고기간**: `보고기간: YYYY년 M월 D일 ~ M월 D일`
3. **1. 무인대차 파트 (김윤회 · 최현빈)** — 지난주 진행 내용
4. **2. 스마트팜 제어 파트 (김희승)** — 지난주 진행 내용
5. **3. 이번 주 계획 (YYYY년 M월 D일 ~ M월 D일)**
   - 무인대차 파트 (김윤회 · 최현빈)
   - 스마트팜 제어 파트 (김희승)
6. **마무리 문장**: `이상 보고 마치겠습니다.`

### 문체 규칙
- 회의 발표용 **서술형 문장** (표·불릿·리스트 사용 금지)
- 문단으로 자연스럽게 이어지는 문장으로 작성
- 존댓말 (`~습니다`, `~하였습니다`, `~예정입니다`)
- 전문가가 아닌 사람도 알아들을 수 있도록 쉬운 말로 풀어 씀
- 로봇 아님 → **무인대차** 로 표기

### 강조 규칙
- 핵심 성과·핵심 계획은 **볼드체(`**...**`)** 로 표시
- 한 파트 안에 볼드 표현이 2~4개 정도가 적정

### 전문 용어 처리
- 처음 등장하는 전문 용어는 짧게 풀어서 설명 (예: 관성센서)
- 설명은 인용 블록(`>`)으로 별도 처리
- 형식 예시:
  ```
  > 참고 — 관성센서란?
  > 무인대차가 얼마나 기울었는지, ... (스마트폰 예시 등 비유 활용)
  ```

### 중복 방지
- "남은 과제" 문단은 만들지 않음 (이번 주 계획과 겹치므로)
- 지난주 미완료 항목은 → "이번 주 계획" 안에 자연스럽게 녹여서 서술

### 완결성과 압축 (최우선 균형)
- **대표에게 구두 보고하는 문서**임. 듣는 사람에게 세부 과정은 필요 없음
- **주제(업무 항목)는 하나도 빠뜨리지 않되, 각 항목은 결과 중심 1~2문장으로 압축**
- 과정 설명·기술적 세부 절차는 걷어내고, "무엇을 했고 어떤 결과가 나왔는지"만 남김
- 인상적인 핵심 수치(예: 오차 8.75m→0.53m)는 1~3개만 남기고 나머지 수치는 생략
- 전문 용어 인용 블록(`> 참고`)은 꼭 필요할 때 1개 이내로만, 없어도 됨

### 분량
- 슬라이드·인포그래픽 등 시각 자료 만들지 않음
- **소리 내어 읽어 2분 안팎 (약 1,000~1,300자)** — 이 길이를 넘으면 디테일을 더 걷어낼 것 (단, 주제 자체를 삭제하지는 않음)

## 5. 참고 — 좋은 예시 (2026년 7월 20일 ~ 7월 24일 보고)

```
스마트팜 주간업무 보고
보고기간: 2026년 7월 20일 ~ 7월 24일

1. 무인대차 파트 (김윤회 · 최현빈)
작업자를 따라다니는 무인대차가 안정적으로 사람을 인식하고, 자기 위치를
정확히 파악하며, 장애물을 피할 수 있도록 만드는 작업을 진행했습니다.

이번 주 가장 큰 성과는 **무인대차가 실제 차량 위에서 작업자를 따라 처음으로
움직였다**는 점입니다. 그동안 무인대차가 자기 위치를 잘못 계산해서 공중으로
붕 뜨는 것처럼 인식하는 문제가 있었는데, 그 원인을 찾아내서 해결했습니다.
덕분에 그동안 못 쓰고 있던 관성센서를 다시 활용할 수 있게 되었습니다.

> 참고 — 관성센서란?
> 무인대차가 얼마나 기울었는지, 어느 방향으로 얼마나 빠르게 움직였는지,
> 얼마나 회전했는지를 감지하는 센서입니다. 스마트폰이 가로/세로를 알아채거나
> 걸음 수를 세는 것과 같은 원리이며, 카메라가 잠깐 사람을 놓치거나 흔들려도
> 무인대차가 자기 움직임을 스스로 감지해 위치를 유지할 수 있게 해주는
> 역할을 합니다.

(이하 생략 — 형식만 참고)
```

## 6. AI에게 전달할 체크리스트

보고서 작성 전 아래 항목을 반드시 확인:

- [ ] 보고기간을 지난주 월~금으로 표기했는가?
- [ ] 지난주 일지의 주요 업무 주제가 하나도 빠짐없이 반영되었는가?
- [ ] 각 항목을 결과 중심 1~2문장으로 압축했는가? (과정·기술 세부 제거)
- [ ] 전체 분량이 낭독 2분 안팎(약 1,000~1,300자)인가?
- [ ] 김윤회, 최현빈, 김희승 세 명의 Daily Work Log만 취합했는가?
- [ ] 스마트팜 관련 업무만 포함하고, 그 외는 제외했는가?
- [ ] 김윤회 · 최현빈은 "무인대차 파트" 로 묶었는가?
- [ ] 김희승은 "스마트팜 제어 파트" 로 분리했는가?
- [ ] 개별 이름을 문장 안에서 언급하지 않았는가?
- [ ] "로봇" 이 아니라 "무인대차" 로 표기했는가?
- [ ] 표·불릿·리스트 없이 서술형 문장으로 작성했는가?
- [ ] 전문 용어는 인용 블록으로 쉽게 풀어 설명했는가?
- [ ] "남은 과제" 문단을 별도로 만들지 않았는가?
- [ ] "이번 주 계획" 을 무인대차 / 스마트팜 제어 두 파트로 나누어 서술했는가?
- [ ] "이상 보고 마치겠습니다." 로 끝맺었는가?
