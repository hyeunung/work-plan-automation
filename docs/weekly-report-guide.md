# 스마트팜·영남대 주간업무 보고 작성 지침

> 이 문서는 매주 월요일 아침 대표이사에게 구두 보고하는 "스마트팜·영남대 주간업무 보고"를 동일한 형식으로 뽑기 위한 지침입니다.
> 자동화 파이프라인(`src/services/executiveWeeklyReport.js`)이 이 문서를 그대로 프롬프트에 실어 Claude에게 전달하며,
> 사람이 AI에게 "이 지침대로 이번 주 주간보고 뽑아줘" 라고 요청해도 같은 형식이 나옵니다.

---

## 1. 요청 방법

새 대화창에서 아래 링크를 함께 던지고 요청하세요.

```
https://github.com/hyeunung/work-plan-automation/blob/main/docs/weekly-report-guide.md
이 지침대로 이번 주 주간업무 보고 뽑아줘.
```

또는 짧게:

```
지침 파일 참고해서 [YYYY-MM-DD ~ YYYY-MM-DD] 주간업무 보고 뽑아줘.
```

---

## 2. 데이터 소스

- **Notion Daily Work Log DB**: 팀원 전원의 일일 업무 기록 → "지난주 진행 내용" 섹션의 근거
- **Notion Weekly Plan DB**: 팀원 전원의 주간 계획 → "이번 주 계획" 섹션의 근거 (이번 주 계획이 아직 등록 전이면, 지난주 미완료 항목과 일지에 언급된 예정 업무로 작성)
- **Notion Tasks / Projects DB**: 각 일지가 어느 프로젝트에 속하는지(관련 Task → Project) → 섹션을 나누는 기준. Projects DB의 `선택` 분류가 `스마트팜-*` 또는 `영남대`인 프로젝트만 보고 대상
- **GitHub `work-plan-automation` repo**: 자동화 코드 (참고용)

---

## 3. 취합 규칙

### 대상 인원
- **Notion Team Members DB 전원.** 사람을 지침이나 코드에 적어 두지 않고 DB에서 그때그때 불러온다.
- 지난주에 일지가 한 건도 없는 사람은 보고에 등장하지 않는다.

### 범위
- **보고자(정현웅)가 대표에게 직접 보고하는 담당 영역만 포함한다: 스마트팜 전 트랙 + 영남대 협력 과제(수질센서 모니터링, 혈당 모니터링 앱).**
- 연구소 자체 업무(EtherCAT, 풍산 트리거, VARO 등)와 외부 프로젝트(DFG, LPD, MIS 등)는 연구소가 따로 보고하므로 **제외**한다. 자동화 코드는 Notion Projects DB의 `선택` 분류(`스마트팜-*`, `영남대`)로 걸러서 수집 데이터에 아예 넣지 않는다.
- 수집 데이터에 없는 프로젝트·업무는 보고서에 언급하지 않는다. "그 외 업무는 생략했습니다" 같은 문장도 쓰지 않는다.
- 스마트팜·영남대 안에서는 특정 프로젝트를 뭉개거나 빼지 않는다.
- 개인 스터디·학습 항목은 "스터디를 통해 지식을 쌓은 것"으로 표현하되, 실무 성과처럼 쓰지 않는다.

### 섹션 묶음 (프로젝트 단위)
- 보고는 **사람이 아니라 프로젝트 단위**로 묶는다. 수집 데이터에 각 일지의 프로젝트명이 붙어 있으니 그대로 따른다.
- 섹션 제목은 `N. {프로젝트명} ({담당자 · 담당자})` 형식. 담당자는 그 프로젝트 일지를 쓴 사람 전원을 가운뎃점(·)으로 나열한다.
- 프로젝트 순서는 수집 데이터에 제시된 순서(지난주 활동량이 많은 순)를 따른다.
- 프로젝트가 연결되지 않은 일지는 보고 범위를 판정할 수 없어 수집 단계에서 제외된다(수집 데이터에 `기타 업무`가 있을 때만 마지막 섹션으로 묶는다).
- 섹션 본문 안에서는 개별 이름을 다시 언급하지 않는다 ("두 사람이", "김윤회가" 같은 표현 금지). 제목의 담당자 표기로 충분하다.
- 같은 프로젝트에 여러 사람이 참여했으면 한 흐름으로 합쳐서 서술한다. 사람별로 문단을 나누지 않는다.

### 기간
- **지난주 월요일 ~ 금요일** (보고기간 표기도 월~금으로. 예: `보고기간: 2026년 7월 20일 ~ 7월 24일`)
- 단, 주말에 기록된 업무가 있으면 내용에는 포함 (기간 표기만 월~금)

## 4. 보고서 형식 (반드시 이 구조 그대로)

### 구성 순서
1. **제목**: `스마트팜·영남대 주간업무 보고`
2. **보고기간**: `보고기간: YYYY년 M월 D일 ~ M월 D일`
3. **1. {프로젝트명} ({담당자})** — 지난주 진행 내용
4. **2. {프로젝트명} ({담당자})** — 지난주 진행 내용
5. … (프로젝트 수만큼 반복)
6. **N+1. 이번 주 계획 (YYYY년 M월 D일 ~ M월 D일)**
   - 위와 같은 프로젝트 순서로, 프로젝트명을 문장 앞머리에 두고 한 문단씩 서술
   - 이번 주 계획이 없는 프로젝트는 "별도 계획이 확정되지 않았습니다" 한 문장으로 정리
7. **마무리 문장**: `이상 보고 마치겠습니다.`

### 문체 규칙
- 회의 발표용 **서술형 문장** (표·불릿·리스트 사용 금지)
- 문단으로 자연스럽게 이어지는 문장으로 작성
- 존댓말 (`~습니다`, `~하였습니다`, `~예정입니다`)
- 전문가가 아닌 사람도 알아들을 수 있도록 쉬운 말로 풀어 씀
- 로봇 아님 → **무인대차** 로 표기

### 강조 규칙
- 핵심 성과·핵심 계획은 **볼드체(`**...**`)** 로 표시
- 한 섹션 안에 볼드 표현이 1~3개 정도가 적정

### 전문 용어 처리
- 처음 등장하는 전문 용어는 짧게 풀어서 설명 (예: 관성센서, HMI, EtherCAT)
- 설명은 인용 블록(`>`)으로 별도 처리
- 형식 예시:
  ```
  > 참고 — 관성센서란?
  > 무인대차가 얼마나 기울었는지, ... (스마트폰 예시 등 비유 활용)
  ```

### 중복 방지
- "남은 과제" 문단은 만들지 않음 (이번 주 계획과 겹치므로)
- 지난주 미완료 항목은 → "이번 주 계획" 안에 자연스럽게 녹여서 서술

### 완결성과 압축 (최우선 균형)
- **대표에게 구두 보고하는 문서**임. 듣는 사람에게 세부 과정은 필요 없음
- **프로젝트와 업무 주제는 하나도 빠뜨리지 않되, 각 항목은 결과 중심 1~2문장으로 압축**
- 과정 설명·기술적 세부 절차는 걷어내고, "무엇을 했고 어떤 결과가 나왔는지"만 남김
- 인상적인 핵심 수치(예: 오차 8.75m→0.53m)는 보고서 전체에서 2~4개만 남기고 나머지 수치는 생략
- 전문 용어 인용 블록(`> 참고`)은 꼭 필요할 때 보고서 전체에서 1~2개 이내로만, 없어도 됨

### 분량
- 슬라이드·인포그래픽 등 시각 자료 만들지 않음
- **소리 내어 읽어 2분 안팎 (약 1,200~1,600자)** — 프로젝트가 많아도 이 길이를 넘기지 말고 항목당 디테일을 더 걷어낼 것 (단, 프로젝트나 주제 자체를 삭제하지는 않음)

## 5. 참고 — 좋은 예시 (형식만 참고)

```
스마트팜·영남대 주간업무 보고
보고기간: 2026년 7월 20일 ~ 7월 24일

1. 무인대차 1차 프로토타입 (김윤회 · 최현빈)
작업자를 따라다니는 무인대차가 안정적으로 사람을 인식하고, 자기 위치를
정확히 파악하며, 장애물을 피할 수 있도록 만드는 작업을 진행했습니다.
이번 주 가장 큰 성과는 **무인대차가 실제 차량 위에서 작업자를 따라 처음으로
움직였다**는 점입니다. 그동안 위치를 잘못 계산하던 원인을 찾아 해결하여
못 쓰고 있던 관성센서를 다시 활용할 수 있게 되었습니다.

> 참고 — 관성센서란?
> 무인대차가 얼마나 기울었는지, 어느 방향으로 얼마나 빠르게 움직였는지를
> 감지하는 센서입니다. 스마트폰이 가로/세로를 알아채는 것과 같은 원리입니다.

2. 영남대 수질센서 모니터링 시스템 (김희승)
영남대학교에 전달할 **제어 화면 1차 시안을 완성하여 검토를 요청**하였습니다.
(이하 생략)

3. 청송농장 운영 (김희승)
청송 농장에서 **수확·선별·포장 98박스 작업**을 현장에서 직접 수행하였습니다.

4. 이번 주 계획 (2026년 7월 27일 ~ 7월 31일)
무인대차 1차 프로토타입은 ... 예정입니다.
영남대 수질센서 모니터링 시스템은 ... 예정입니다.

이상 보고 마치겠습니다.
```

## 6. AI에게 전달할 체크리스트

보고서 작성 전 아래 항목을 반드시 확인:

- [ ] 보고기간을 지난주 월~금으로 표기했는가?
- [ ] 수집 데이터에 등장한 프로젝트가 하나도 빠짐없이 섹션으로 반영되었는가?
- [ ] 지난주 일지의 주요 업무 주제가 하나도 빠짐없이 반영되었는가?
- [ ] 각 항목을 결과 중심 1~2문장으로 압축했는가? (과정·기술 세부 제거)
- [ ] 전체 분량이 낭독 2분 안팎(약 1,200~1,600자)인가?
- [ ] 수집 데이터에 없는 연구소 자체 업무·외부 프로젝트를 언급하지 않았는가?
- [ ] 섹션을 사람이 아니라 프로젝트 단위로 묶었는가?
- [ ] 섹션 제목을 `N. 프로젝트명 (담당자 · 담당자)` 형식으로 썼는가?
- [ ] 섹션 본문 안에서 개별 이름을 언급하지 않았는가?
- [ ] "로봇" 이 아니라 "무인대차" 로 표기했는가?
- [ ] 표·불릿·리스트 없이 서술형 문장으로 작성했는가?
- [ ] 전문 용어는 인용 블록으로 쉽게 풀어 설명했는가?
- [ ] "남은 과제" 문단을 별도로 만들지 않았는가?
- [ ] "이번 주 계획" 을 프로젝트 순서대로 서술했는가?
- [ ] "이상 보고 마치겠습니다." 로 끝맺었는가?
